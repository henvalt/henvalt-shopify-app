# HENVALT Web Pixel

Subscribes to Shopify storefront events:

- `page_viewed`
- `product_viewed`
- `product_added_to_cart`
- `checkout_started`

The pixel sends minimized events to the tenant-specific Cloudflare collector. It does not collect email, phone, address, cookies, or Shopify customer IDs. It is inert until both collector URL and tenant-scoped public key are configured.

## Payload and privacy

- `client_id` is an anonymous browser/session reference, never customer identity.
- `page_url` is HTTPS origin + path only; query strings and fragments are stripped in both pixel and collector.
- Product and cart fields are minimized identifiers/title/quantity.
- `checkout_reference` is sent only for `checkout_started` to support tenant-scoped correlation with a later signed Shopify checkout webhook.
- Customer privacy configuration requires analytics consent, does not require marketing consent merely to measure browsing, and declares `sale_of_data = "disabled"`.
- Pixel events never establish customer identity or marketing consent and must never directly trigger recovery email.

## Implemented backend

The Cloudflare collector is deployed and calls the narrow Supabase RPC using only the publishable key. Supabase migrations for pixel keys, rate limiting, session aliases and ingestion are applied. The database stores only the SHA-256 digest of the public key, validates exact allowed origin and tenant state, applies a global per-key limit, and writes idempotent canonical events.

The alias bridge supports pixel-first and webhook-first event ordering. Anonymous events remain ineligible for email until trusted Shopify events establish customer identity and current marketing consent.

The collector currently writes directly to Supabase. It is intentionally separate from Shopify webhook HMAC verification and is not yet routed through the existing `HENVALT_INGEST` workflow.

## Shopify deployment status

The extension source and root `shopify.app.toml` are committed on `feature/web-pixel-foundation`. The root config includes the HENVALT Client ID, app URL, OAuth callback, pixel scopes, and collector network source.

The extension still needs an official UID generated by Shopify CLI, an app version release, test-store reauthorization, tenant-key provisioning, and `webPixelCreate` activation. No live Shopify storefront event has yet been verified in Supabase.

See the root README for the mobile-friendly GitHub Codespaces procedure. Do not claim browse recovery is active until the full end-to-end test passes.
