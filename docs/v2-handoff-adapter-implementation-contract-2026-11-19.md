# V2 handoff adapter implementation contract

Status: candidate code and tests on the preparation branch only. This is not an n8n workflow export and is not imported by any active workflow.

## Files

- `n8n/v2-handoff-adapter.mjs`: isolated executable reference adapter.
- `tests/n8n-v2-handoff-adapter.test.mjs`: no-provider-network tests using injected fetch and finish callbacks.

The adapter is intentionally kept outside the deployed Edge Functions. The current n8n runtime has not been configured or verified to import repository-local ESM modules, so do not attempt to import this file into the active workflow. Port its allowlists and response rules into a reviewed n8n draft using native Code/HTTP Request nodes, or explicitly configure and verify a supported module distribution mechanism first.

## Input contract

One claimed item is accepted only when it contains:

```json
{
  "work_type": "CHECKOUT_INTERVENTION",
  "work_id": "11111111-1111-4111-8111-111111111111",
  "lease_id": "22222222-2222-4222-8222-222222222222",
  "worker_id": "worker-v2-01",
  "correlation_id": "corr-123"
}
```

The correlation ID is generated by the orchestrator and is not a customer identifier. Unknown work types, malformed UUIDs, unsafe worker IDs and invalid correlation IDs fail validation before an HTTP request.

## Routing and request allowlists

- `CHECKOUT_INTERVENTION` routes only to `henvalt-shopify-contact-delivery-v2` with body `{"intervention_id":"<work_id>"}`.
- `PIXEL_OPPORTUNITY` routes only to `henvalt-shopify-pixel-delivery-v2` with body `{"opportunity_id":"<work_id>"}`.

The adapter never forwards tenant IDs, Shopify connection IDs, customer identifiers, email addresses, recipient references, subjects, HTML/text, product/cart details, tokens, or provider credentials in the JSON body. The service bearer token is sent only in the Authorization header and must never enter execution data or logs. Do not enable full request/response header logging.

## Response and lease mapping

| Result | Lease outcome | Rule |
|---|---|---|
| 2xx + `accepted: true` + status `submitted`, `accepted`, or `handed_off` | `HANDOFF_ACCEPTED` | Explicit positive handoff only |
| 2xx + known ambiguous provider status | `DEFERRED` | Provider reconciliation required |
| 400, 404, 410, 422 | `TERMINAL` | Permanent request rejection allowlist |
| 401, 403, 409, 429, 5xx, timeout, malformed JSON, unknown status | `DEFERRED` | Conservative; never infer acceptance |

The current Edge Functions return `202` with `accepted: true, status: submitted` only after a recorded submission; their ambiguous outcomes use explicit non-success statuses. Any unknown response is deferred.

Finish the lease exactly once using `finish_shopify_recovery_work_claim_v2` with the original `lease_id`, `worker_id`, the classified outcome, and a bounded retry interval. The SQL function itself validates the active lease and rejects stale lease IDs. Do not retry a possibly submitted provider call as a fresh send.

## Safety boundary

This adapter is only the orchestration-to-Edge-Function handoff. It does not call MailerSend, authorize a send, create a delivery permit, resolve a recipient, or process signed provider events. The Edge Functions retain those responsibilities and their independent authorization checks.

The adapter tests inject a fake fetch implementation and fake lease finisher. No network request to Supabase, Shopify or MailerSend is made by the test suite. The adapter has not been connected to the active n8n workflows, and this document does not authorize a workflow import, execution, activation or production cutover.
